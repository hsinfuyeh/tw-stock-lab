# tw-stock-lab 本機研究升級：第一階段設計

日期：2026-10-07。狀態：使用者已確認建立本機開發分支並接續本設計；僅本機執行。

## 目標與執行範圍

使用者希望借鏡 anti-gambling-trader-tw 的績效驗證，以及 ToAlpha 的市場與產業研究流程，由 tw-stock-lab 自行實作。資料直接取自官方來源，不使用兩個工具的資料服務或程式碼。

本階段完成三項：成本後績效基準、市場與產業摘要、每日候選結果追蹤。成功標準是能在本機核對候選的固定交易規則結果、理解市場與產業背景，並明確知道資料和樣本的不足。本階段不承諾提高命中率。

僅開發和預覽本機版本，伺服器綁定 127.0.0.1。不得 push、觸發 GitHub Actions、部署 Pages、部署或修改 Cloudflare。允許取得公開官方資料以供本機測試。

## 已確認的基礎

- 基準提交：444f709。現有 MarketService 保存每日快照、完整合格標的排序及十日到期結果。
- two_week.outcome 已分開記錄觸及目標、較保守的可成交機會和到期收盤毛報酬，尚未提供本策略固定出場規則的淨報酬。
- analytics.net_return 已有股票／ETF 成本計算，可作共用計算入口。
- 公司基本資料端點實際回傳產業別，但 listed_universe 尚未保留。
- 現有本機 API 與靜態發布共用網頁。新增本機功能必須處理舊快照缺欄位的情況。

## 本機資料與伺服器

建立獨立的本機開發資料目錄，透過現有 --data-dir 啟動，不修改既有 data 的研究記錄。開發資料與日誌不得納入 Git。

優先使用既有已保存快照作介面與相容性核對；若本機快照不完整，明示資料不足，再以官方資料補齊。測試固定樣本須與真實研究資料分離，不能冒充真實績效。

沿用 Python HTTP 伺服器，在空閒本機連接埠開啟預覽。由本機 API 提供新報告，瀏覽器只向本機請求資料。啟動本機模式時不得載入雲端觸發流程。

## 成本後交易結果

保留現有 two-week-v2 結果與原排名，新增獨立 trade-policy-v1 的模擬結果。不同版本不混合統計，不改寫原始候選。

固定基準：訊號後下一個實際交易日開盤模擬買入；進場日算第一日；最多持有十個交易日；目標為依升降單位向上取整的毛價差 +5%；不新增停損。

出場規則：

1. 買入當日若最高價高於目標至少一個跳動單位，以目標價模擬賣出；只碰到目標不假設成交。
2. 後續交易日若開盤已高於目標，以該日開盤模擬賣出；否則最高價高於目標至少一個跳動單位時，以目標价模擬賣出。
3. 未滿足以上條件，第十日收盤模擬賣出。
4. 單一價格的進場日、缺交易日或價格無效，沿用保守的未成交／不可比較狀態。遇已辨識的公司行動窗口，不產生可比較淨報酬。

開盤和日高成交均屬日線模擬，不能稱實際成交。另保存只觸及目標的標籤；第一版不製造實際成交機率。

淨報酬沿用既有成本公式：股票賣出稅 0.3%、ETF 0.1%，雙邊手續費各 0.1425%、滑價各 0.05%。這些是研究假設；新規則明確標示毛 +5% 不等於淨 +5%。計算公式只有一份，費用不重複扣除。

結果保存訊號／進出場日期、原排名、進出場價格、目標價格、出場原因、淨報酬、版本及證據識別。持有期間不利變動只使用實際模擬出場日前日線，並說明出場當日盤中順序未知。

## 績效報告與候選追蹤

以前十名對照同日全部合格標的，分股票、被動 ETF、主動 ETF。每個訊號日先作等權重平均，再跨日彙總，避免標的數較多的日期占更大權重。

輸出已成熟訊號日數、可比較／未成交／不可比較筆數、目標成交假設達成比例、平均和中位淨報酬、平均獲利／虧損、獲利因子、前十名對基準的日平均差額。無虧損或樣本缺漏時顯示不可計算，不用無限大或零替代。

以上是重疊候選實驗的描述統計，不當作可投入固定資金的投資組合報酬。第一版不提供 Sharpe、資金曲線最大回撤、統計優勢認證或新的個股機率。

候選追蹤顯示原訊號日、原排名與理由、進場資訊、已經過的實際交易日、等待到期／未成交／不可比較／已評估狀態及已成熟結果。未到期不計入完成績效；原候選日期與理由不被今日行情覆蓋。歷史沒有足夠日線時明示無法核對。

## 市場與產業摘要

從同一快照的上市普通股計算，ETF 不納入股票市場廣度。僅使用當日價格及所需完整窗口；列出分母、排除數及資料日。

市場指標：上漲／下跌／平盤家數、站上二十日均線比例、股票等權重日報酬、總成交金額相對前二十日均值。各指標獨立判斷有效窗口，不因其中一項不足而把全部變成零。

產業指標：官方產業別、同日報酬中位數、上漲比例、成交值占比、二十日報酬中位數、候選數。有效樣本少於五檔時顯示樣本偏少，仍可查看數字，不授予強弱判斷。

產業分類記錄來源與首次取得時間。沒有產業欄位的舊快照歸為未記錄，不使用今天分類回填成當時已知。首次真實完整產業摘要需重新取得官方公司清單並生成本機快照。

本階段採可核對的描述指標，不製造綜合市場風險分數，也不改變候選排序。

## 模組與介面

- data.py／service.py：保留產業欄位和分類取得時間；新增結果版本的本機保存與讀取。
- 新增獨立績效模組：交易模擬、按訊號日彙總、基準比较，避免把績效公式塞入前端。
- 新增獨立市場摘要模組：處理市場／產業計算與覆蓋率。
- server.py：提供本機研究報告 API，支援指定快照；舊快照無新增欄位時回傳明確不足狀態。
- web：首頁加入緊湊市場摘要和產業表；新增績效／結果追蹤入口；說明以既有懸浮提示呈現。資料日與樣本狀態維持可見。

資料簽章需包含本階段計算版本及新增來源版本，避免同一行情日期的新功能被舊快照快取跳過。重新分析保留原訊號，結果與分析版本分開保存。

## 錯誤與相容性

官方分類取得失敗時可讀既有本機快照，顯示分類日期和缺漏；不得以空結果覆蓋有效資料。市場與績效報告失敗各自顯示原因，不能以零報酬偽裝成功。

原本搜尋、今日名單、其他排行、個股詳情與社群功能繼續可用。靜態模式若沒有新增報告，呈現未產製狀態，不呼叫本機 API。這次不改動雲端工作流程與 Worker。

## 驗收

1. 手工可核算案例驗證進場、只觸及／高過目標、跳空、到期出場、股票／ETF 成本、缺日、鎖價、公司行動與尚未成熟。
2. 固定小型股票集合核對廣度分母、等權重、產業中位數、成交值占比及缺欄位行為；不得重複計入 ETF。
3. 驗證按訊號日等權重基準、原候選不可回寫、不同分析版本隔離、重新分析後資料簽章變更。
4. 本機 API 和桌面／手機瀏覽器核對市場摘要、候選追蹤與績效頁；真實資料標示日期，測試資料不混入。
5. 執行既有 Python／Node 測試與新增必要測試。核對本機伺服器僅綁定 loopback，沒有雲端觸發或部署。
