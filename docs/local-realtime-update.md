# 本機按鈕即時更新

2026-09-30：使用者選擇本機版，社群與行情分別由按鈕啟動，不使用個人 Threads 帳號。

## 執行

`python app.py serve --port 8765`；開啟 http://127.0.0.1:8765/ 。此入口使用全市場 MarketService。若已將公開行情備份匯入 `logs/local-live-state`，可用 `python app.py serve --port 8765 --data-dir logs/local-live-state` 沿用資料。目錄包含公開行情與分析，不提交 Git。

GitHub Pages 或 `python -m http.server` 只能讀靜態報告，不提供抓取 API。靜態版的「讀取雲端報告」與本機版的「更新行情資料」明確區別。

## 行情

按更新立即啟動既有背景工作，重新確認可變官方來源（清單、休市日、當月交易日、最近5個交易日行情），保留定稿歷史快取。執行中只輪詢 `/api/job` 的進度，完成後讀取新研究結果，避免反覆傳輸全市場資料。資料日、原報告時間與來源檢查時間分開；官方資料未變不改寫原報告的產製時間，明示資料日未變更。初次缺少歷史資料或需重新分析全市場時可能較久。

## 社群

`POST /api/social/update`，JSON 僅接受 `{"window":"24h"}` 或 `{"window":"7d"}`；立刻返回202與工作ID。`GET /api/social/job` 查詢進度。單一本機服務同時只允許一個社群工作。頁面1.5秒輪詢，期間選單及更新按鈕停用；刷新頁面可重新取得尚在執行的工作。行情更新與社群工作分開。

來源：PTT按所選時間窗過濾公開主文，仍受12頁／150篇／5分鐘上限；Dcard手動更新重新嘗試公開 API，403明示失敗；Threads未登入公開搜尋未接通，明示 unavailable，沒有使用個人帳號、Cookie或官方 token 作為替代。不能宣稱三平台均即時接通。整批來源都不可用時，保存舊排行，由工作狀態顯示本次失敗；部分成功時產生僅已取得來源的合計。

時間窗以按鈕啟動時間為上限；任務進行中新發布、晚於該上限的文章不計入本次。舊的已辨識貼文保留最多七天，近24小時排行只算該窗口。爬取上限不等於完整平台資料。

## 驗證

單元／整合回歸覆蓋：工作去重、期間驗證、來源進度、無個人帳號路線、整批失敗保留、POST202、跨來源拒絕、前端輪詢後刷新，以及行情明確更新繞過可變快取。實際本機按鈕驗證結果與畫面保存在忽略的 logs 目錄。
