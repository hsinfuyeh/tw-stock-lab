# 社群聲量排行設計

日期：2026-09-29。使用者已選擇 GitHub 雲端收集；Threads 授權與 Dcard 可用來源待確認。

## 目標

在 tw-stock-lab 增加獨立「社群聲量」頁籤，統計 PTT Stock、Dcard 股票板與 Threads 公開台股討論提及的股票。每頁最多十檔，上一頁／下一頁。提供近 24 小時及近 7 天切換，以及全部／各平台篩選。沿用固定欄寬、靠左與既有字級。

聲量是可核對的討論篇數，不是看多比例或買進推薦。此資料不參與現有今日名單量價分數。

## 已確認的來源可用性

- PTT Stock：公開索引 HTTP 200，2026-09-29 本機實測。
- Dcard 股票板：直接 API HTTP 403；正常 Chrome 公開看板可顯示文章。網站可讀不等於 GitHub Actions 能穩定收集。
- Threads：此前已透過 Chrome 讀取公開串文；Meta 提供貼文搜尋 API，但本專案尚未接入授權。搜尋結果不視為全平台完整母集合。
- 既有 browser-workflow-engine 已安裝，三平台目前沒有本任務的既有收集 playbook，需要逐站 discovery 與 sample 驗證；本機引擎不能直接視為雲端可用。

## 執行方式

執行雲端方案：

PTT 以公開 HTML 接入；Threads 使用官方搜尋 API，授權僅由 GitHub Secret 提供；Dcard 嘗試公開 API，回傳封鎖時不繞過，標示來源失敗。未接通的來源不計為零。雲端不依賴本機瀏覽器引擎，也不另建通用爬蟲引擎。

初版範圍：PTT 最近至多 12 頁、Dcard 股票板最近至多 5 頁（每頁 100 篇）、Threads 搜尋「台股」「股票」「ETF」，每詞至多 3 頁（每頁 50 篇），均只納入發布時間位於最近 7 天的公開主貼文。上限或搜尋取樣會明示，不能宣稱全平台完整統計。PTT 大量閒聊留言與所有平台留言不納入初版。

## 原始記錄與範圍

每筆記錄保存平台、穩定貼文 ID、原文 URL、發布時間、收集時間、標題／可讀文本及辨識的股票代號。憑證與瀏覽器登入資料不進入 Pages、Git 或公開 JSON。

各批次保存起訖時間、入口／搜尋條件、掃描貼文數、頁數、是否掃描至時間下限，以及任何截斷、登入或來源錯誤。未取得準確發布時間的文章不得納入 24 小時／7 天統計。

Threads 的搜尋條件與每次收集上限需在 discovery 後寫入來源設定，並在頁面呈現。不得將熱門結果樣本當成全部台股討論。

## 辨識與去重

- 使用股票代號及正式名稱，台／臺與全半形統一；名稱別名需要可追溯的明確設定。
- 代號須有邊界，避免 2330 誤匹配 23301、日期、金額或文章 ID。單純數字但缺乏股票語境者不採計。
- 易與一般詞彙混淆的公司名稱，需代號或明確股票語境才採計。
- 同平台同貼文 ID 只保存一次，同篇同股票只計一次。
- 同篇提及多檔股票，各股票分別加一；引用舊文章不把舊文重複當成新文章。
- 跨平台轉貼在各平台分別計數；合計表示平台貼文數相加，不宣稱是不同作者或不同觀點數。

## 排行與介面

主排序為時間窗內觀察到的不同貼文篇數；同分以代號排序，不用未校準的 AI 情緒分數打破同分。

欄位：排名、股票代號／名稱、合計篇數、PTT 篇數、Dcard 篇數、Threads 篇數、原文依據。點開依據列出各篇時間、平台及原文連結，並能開啟既有個股詳情。

頁面顯示社群統計時間與最後收集時間，與行情資料日分開。各平台使用成功／部分取得／未接入／失敗狀態，未取得顯示「—」；已成功收集但無提及才能顯示 0。來源缺漏時合計須標示為已取得來源的部分合計。

7 天資料尚未累積或回填完成時，顯示實際涵蓋期間。沒有前期對照時不顯示成長率。暫不加入留言全文、情緒分析或按讚加權。

## 驗證

1. 各平台 1–10 筆真實小樣本，核對貼文 ID、時間、URL 與內容辨識。
2. 在既有爬蟲引擎建立可恢復的來源工作，驗證分頁、終止、空資料、載入、登入／封鎖與去重分支；未驗證的分支明確排除。
3. 測試同篇重複提及、代號碰撞、台／臺、含多檔股票、引用舊文、窗邊界、失敗來源及不完整涵蓋。
4. 測試靜態匯出不帶憑證、每頁十檔、篩選後回首頁與原文連結。
5. 本機瀏覽器核對真實排名與手機顯示，再發布；只有實際收到來源資料才能聲稱來源已接通。
